## 1. 打开项目，开始第一轮

使用部署好的入口打开浏览器。本轮开发候选入口：

```bash
python3 /home/workspace/DevFlower/.local/open-guided-development.py
```

正式 Stable 完成晋升后，日常唯一推荐入口为：

```bash
python3 /home/workspace/DevFlower/.local/open-devflower.py
```

点击左侧“打开文件夹”，选择要处理的具体项目文件夹。窗口浏览的是运行工作台的这台电脑。可逐级进入目录、返回父目录或粘贴绝对路径；成功后顶部会显示路径和环境。工作台、认证和历史运行数据所在的目录可以有保护限制；浏览项目记录与允许 Agent 执行是不同操作。

试用请在 `/home/workspace/claude_workspace/DevFlower测试` 下建立自己的测试文件夹。先放一份没有敏感信息的说明文档，用只读模式试一轮。

首次打开可点击“新手向导”，依次完成打开目录、选模板、配置、填写任务、开始运行。向导可以关闭后再打开。

## 2. 建立和保存工作流

最简单的流程是“输入 → Agent → 结果”。从右侧工具库添加节点，拖动输出端口到下游输入端口连接；也可选择示例，或在右侧 AI 助手中描述需求、上传流程图。

点击 Agent 设置工具、模型和工作方式。工具是 Codex、Claude Code 等执行客户端；模型属于所选工具。刷新模型后选择实际目录中的模型和强度，调用失败会显示真实原因。普通使用不需要手动登记模型、填写确认意见或另发计费验证请求。

初始化提示词说明本轮共同背景，每轮提示词说明该节点现在要做什么，输出与交接要求说明结果应如何交给下游。先用 Ask 只读；需要修改项目文件时再选择 Agent 并核对本次范围。

AI 助手是 DevFlower 内置的独立助手，不借用编程客户端。当前 DeepSeek 连接在本机保存，重新打开、切换工作区或更新版本后恢复；留空密钥表示保留现有密钥。连接文件是 `/home/silver/.config/devflower/devflower-agent-connection.json`，只保存于本机私有目录，不放入项目或云端；不要分享该文件。助手可解释软件、诊断公开源码中的错误、提出画布修复，不会凭回答直接批准交付。

AI 生成的是草稿。点击“检查工作流”，处理错误，再实际运行。格式正确不等于流程一定正确；条件必须读取真实结构化输出，汇合后的数据仍保留各个来源。提案失败时原草稿保留，可在同一助手对话要求根据具体错误修正。既有输入/输出数据合同不能因只改提示词而消失。

点击“保存”保留当前设计；点击“收藏为模板”保存可复用副本。模板不复制旧运行权限或冒充原生会话。撤销、重做、框选、复制、适应画布与专注画布都在画布工具栏。

## 3. 提交任务，查看真实运行

在底部“本次任务”写清目标和完成条件，点击“开始运行”，核对本次工作区、模型、权限及预算后开始。普通任务不要求手写确认意见；显式人工节点和 Git 交付仍有独立边界。

开始后查看运行总览、节点状态和活动记录。正在启动、正在恢复、正在执行、等待输入与状态待确认是不同状态。页面刷新只恢复查看，不应重复启动模型；网络中断时先核验真实状态，不要连续重发。

点击节点看任务、上游输入、回答和可见工具活动。高级区可检查实际请求与 Provider 回执。点击连线看这一轮真正传给下游的内容；下游收到的是连线选定的结果及启用的任务目标，不是自动复制全部聊天历史。

暂停停止调度新节点，当前调用可能继续。停止只取消本任务拥有的执行进程。关闭标签或面板仅关闭显示；“关闭此终端”才结束该终端进程，原生历史保留。

原生终端会恢复对应 UUID。恢复完成后再输入；本地终端接入与工作台共享同一个 PTY，并通过明确接管切换键盘输入权。另一端可以查看，旧输入者不能继续写入。结果未确认时先读取真实状态，不盲目重发。Codex 桌面是否连接同一个 PTY与是否能读取同一个原生会话库是两件事，界面不会用复制记录冒充同步。

Claude Code 与 Codex 使用同一个会话管理入口。打开对应工作区后，从左侧筛选 Claude Code，查看历史或打开已有受管会话；原生记录继续保存在原位置。CLI 通常在 `~/.claude/projects/<项目>/<原生ID>.jsonl` 保存内容；桌面 Code 标签页还维护自己的会话索引，桌面ID与CLI ID可不同，须依据实际 `cliSessionId` 和工作目录对应。普通桌面 Chat 属于另一类对话，不能把它当作 CLI 会话恢复。不要移动或复制两端记录来制造同步。

本机已用实际 DevFlower 解析器核验3条桌面 Code 索引均可定位对应 CLI 原始记录；这仅证明历史关联。外部未受管 Claude 会话的读取、原生恢复和跨客户端输入接管分别核验；目前跨桌面实际接管尚未验收，不能把可读历史当作已取得写入权。官方桌面迁移命令还受平台和登录方式限制，见 [Claude Code 桌面说明](https://code.claude.com/docs/en/desktop#coming-from-the-cli)。现有中转站配置和原生历史保留。

## 4. 完成后继续下一轮，查看历史

不必重新搭建流程。在历史任务中选择“用此流程开始下一任务”，或返回编辑草稿，填写新的任务目标后再开始。新一轮有自己的运行记录，上一次不会被覆盖。

“整轮对话”按工作流、任务与节点分区查看，再按该分区内的时间顺序阅读提示词、回答、交接和工具活动。左侧可按 Provider 或 Workflow 分类、折叠、搜索；会话名称和实际原生身份保持关联。点击文件引用可选择用 VS Code 打开或复制路径。

工作区的工作流和可见对话记录保存在该目录的 `.devflower` 下；助手 API 连接是本机私有设置，不存入项目。后台进程、控制状态及完整原生历史还有各自存储，项目里的记录不能冒充仍在运行的进程。

删除草稿、关闭会话标签、在 DevFlower 回收站隐藏记录和删除原生历史是不同操作。批量操作前确认范围。软件更新和分支整理不会自动清空 Codex/Claude 原生会话。

## 5. 报错、成本与研发档案

先点“检查工作流”，点击具体问题定位节点或连线；修改后重新检查。可把检查结果发给 AI 助手，让它解释或提出修复草稿。应用前核对变更；失败记录保留，不能因为助手说“成功”就当运行完成。

模型不可用、认证或配置变化时，以实际报错为准；不要改成其他模型却声称原模型成功。显示“状态待确认”时查看活动区及原生会话，不用反复点击开始解决。

节省成本时优先单 Agent，只在需要独立检查时加审核者。仅传递必要结果，避免完整历史复制；复杂并行与循环会增加调用数。确定性条件与规则路由本身不额外调用大模型，循环达到上限会停止，不能当作成功。

DevFlower 最初的研发记录功能仍保留：`project/devflower` 分支保存五节任务 README、任务状态和索引；源码交付在 `main`。它与软件工作区里的 `.devflower` 运行历史各有用途。可以导出某轮对话作为证据，再把结论与必要摘要写入研发档案；软件不会默认把密钥、原始会话、截图或大日志上传到 GitHub。
