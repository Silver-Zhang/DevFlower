# Agent 工作台

默认是独立的 Development 预览；部署者也可使用外部已批准的固定 Stable 副本，工作台本身不能签发批准。旧 Studio、v1/v2 草稿、授权和历史仍由原入口读取；v3 工作流另存，不迁移正在执行的旧任务。

## 日常操作

1. 从部署者提供的“打开工作台”入口进入。顶部及文件夹环境显示运行时核验的 Development 或 Stable 身份；私有登录地址不要公开分享。
2. 点击“打开文件夹”，在标明运行器机器的窗口选择目录。可返回父目录、选择已批准位置或最近目录，也可以取消。打开目录只读取信息，执行和写入需要当次授权。
3. 在右侧工具栏选择输入、Agent、条件、智能路由、汇合、循环、人工确认、输出、结束、验证和交付节点，或从“示例”开始。工作台支持顶部切换浅色、深色或跟随系统，采用左侧工作流/会话导航、中央自由画布、右侧工具/参数检查器、底部活动区。点击节点默认在右侧配置，画布为检查器预留空间；也可取消固定。拖动节点调整布局，从右侧连接点拖到下游左侧连接点。画布底部工具栏可框选、多选、缩放、适应画布、复制、粘贴、删除、对齐与分布、撤销和重做；空格或中键平移，滚轮缩放，缩略图导航。左侧导航、右侧检查器和底部活动区可拖动边缘调整大小；导航可收起，尺寸保存在本浏览器。从端口拖到空白处可搜索并添加下游节点；双击或右键空白画布可添加节点，拖入工具库节点可定位放置。节点右键提供复制、副本和删除，多选仍保持分组操作；连线旁的加号可插入节点，一次撤销恢复整个操作。复制 Agent 会新建原生会话。点选连线可改标签、指定交接字段或在连线上插入 Agent。
4. 基本页分别设置名称、职责、工具、会话、模型、强度和 Ask/Plan/Agent；提示词页设置初始化、每轮任务、输出要求；高级页限制权限、上下文、超时和预算。模型目录发现、部署授权、认证配置、实际推理成功是不同证据。发现但未获部署授权的模型不可作为可执行选择。已有会话显示其原始绑定配置；不能把新建会话的默认 Provider 用于恢复。
5. 填写任务，保存后点击“开始运行”，核对目标、权限及预算，再确认。运行自动打开冻结画布；修改下一次流程需点击“编辑草稿”。历史运行可在画布工具栏切换。
6. 在节点上看真实状态、轮次、等待对象和结果；点连线查看实际交接。底部可展开事件和实际发送内容。暂停只停止新节点调度，当前进程继续；停止取消本任务拥有的进程。网络中断显示“状态未确认”，可点击“核验并恢复”，不能通过此按钮绕过原生完成回执或重发不确定的回合。进程身份、候选或回执不可靠时会明确拒绝恢复；已持久化终止的未确认运行只供查看，需另行授权新运行，勿重复启动。
7. 左侧搜索名称并打开同一原生会话。默认聊天显示可见消息；Claude 等工具把最终回答放入结构化输出时，下方直接显示“结构化执行结果”，标明运行、节点、完整轮次和当前流程状态。这些是已完成回合的实际结果，不冒充原生文本消息，不代表审核或交付批准。刷新页面会从当前工作区的会话索引重新打开上次会话并读取持久记录。完整请求、工具活动仍默认折叠；仅在 Provider 明确提供公开摘要时另列摘要；不展示隐藏推理。会话管理明确区分 DevFlower 别名/分类、原生改名/归档、可恢复回收站；没有自动过期或永久删除。原生终端页点击“打开同一原生会话”，核对原目录、Provider、模型和强度后确认；工作台在本机 PTY 恢复对应 CLI，不要求手写恢复命令。终端只读挂载源码，与工作流共用原 HOME 的独占写入锁。首次打开专用 HOME 可能出现原生工具自身的配色或目录提示；框架不会代替操作者确认这些提示。关闭标签仅断开显示；“关闭此终端”停止其进程，原生历史保留。浏览器刷新或重新连接只读取已存在的 PTY，不重复启动或重发输入。输入结果不明时停止并标记需核验；服务重启不能冒充恢复丢失的 PTY。终端输出仅保留在服务内存，受大小和30分钟预算限制。

## 可执行语义与边界

- 顺序图、显式 fan-in 汇合、类型化条件和最多五轮的循环由确定性调度器执行。无界环和隐式多路 Agent 输入被拒绝；未选择分支显示跳过。汇合按运行、节点路径及完整祖先轮次关联输入。默认等待全部输入；条件分支之后可显式选择“汇合已选择分支”，仍等待所有上游终态后排除未选分支，失败/取消不会作为完整成功汇合。相同来源和目标拒绝重复连线。
- 每个 run+节点路径只拥有一个原生会话；首轮合并发送一次本次初始化，之后循环不重复。新运行即使恢复同一 UUID 也追加本次初始化，保留原历史。模型输出不是运行状态、独立审核或交付批准。
- 历史接口的 `messages` 保留原生可见消息；`execution_results` 单独投影已完成 Agent 激活的 `output.answer`，按执行起始时间排序，不从 StructuredOutput 工具输入猜测成功。关联同时核对工作区、cwd、Provider、HOME/配置根、原生 UUID，以及 run/节点/chat 绑定；完成回执还须匹配 UUID、请求模型/强度和成功进程结果。失败、取消、未确认激活及缺失/矛盾回执不产生结果。已完成回合若属于失败或状态未确认的流程，仍标出该流程状态，不宣称流程成功。相同回答的不同回合分别保留；原生文本已显示的同一回答不重复展示正文。查询结果按脱敏后的可见回答过滤，不能通过隐藏结构化字段命中；左侧搜索仍仅搜索名称与 Provider。此读取路径不恢复运行、不改写原生历史或 Controller 状态。
- 两个只读 Agent 可以并发；可写节点与同一源码的其他节点互斥。Ask/Plan 使用外层只读挂载，Agent 只能修改授权工作区；Git 元数据另行只读。提示词保护不能替代这些强制边界。
- 传递最终回答、结构化字段或附件引用，不默认复制聊天历史。点选连线可看来源/目标 activation、完整轮次、实际字段和内容以及发送/接收阶段；点选下游节点显示初始化、职责背景、每轮任务、当前上游输入与输出要求组成的真实请求。交接先去掉私有回执、凭据字段和已知密钥，再选择字段；保留来源，超过预算明确截断，接收方重新核验附件访问权和内容哈希。上游建议不能增加权限。
- 原生恢复要求原 HOME、cwd、真实 UUID、模型/强度、记录身份与空闲状态均可核验。导入、多 cwd 或原环境不明的记录只查看或明确复制可见上下文新建。原生分叉创建新 UUID，保留父记录；独立审核不得复用开发会话。
- 状态与事件存储在 SQLite 事务中。重复启动必须匹配同一授权；恢复先检查真实进程、源码、原生记录和独立完成回执。结果不明的回合及原生元数据操作停止等待核验，禁止盲目重发。
- 验证/交付节点只接受部署者固定配置的外部执行器，浏览器不能提交命令。没有配置时显示具体缺项；没有真实审核、有效测试及远端读回不得声称交付。该 Development Controller 的研发由外部固定监督审核，不允许自批自身。
- `tools/devflower_stable_bridge.py` 是连接已授权 Stable 运行的部署适配器：验证节点核验 Stable 实际测试的完整套件、非零计数、进程与原始回执；交付节点重新执行 Stable 的完整门禁并正常推送、读回。中断后查询远端，不盲目重复推送；两库部分成功如实保留。它不会创建授权、批准 Stable 或把画布中 Agent 的 ACCEPT 当独立审核。
- Copilot 未通过本机认证、隔离执行及实际推理验证前不可选。原生 ACP 能力探测或空会话建立不等于模型验收。Provider 不可用会失败并跳过依赖节点，不伪造回答或换模型。

## 部署与开发

前端静态资源随仓库提供；普通启动不需要 Node/npm。部署者需 Python 3.11+、Git、Linux bwrap、显式隔离的原生工具及只读认证挂载。服务只监听 127.0.0.1，按端口隔离浏览器能力，不使用跨 localhost 端口的认证 Cookie；禁止将它直接暴露到公网。

高级部署入口是 `tools/devflower_workbench.py`，明确传入 operator、policy 及完整候选哈希。策略中的模型来自原生发现或有来源标注的显式登记；模型和 effort 沿用用户批准配置。源码变化需生成新的 Development 快照与配置 pin，不能覆盖运行中的 Stable。

正式 Stable 启动在 operator 中增加 `stable: {"record": "<外部批准记录绝对路径>", "sha256": "<外部固定的记录哈希>"}`，保留原 kind 和存储/HOME 路径。新 v3 必须使用 [version 2 来源证明](STABLE_PROVENANCE.md)：外部固定的实际 native hard-ACCEPT 结果、精确合同、旧固定 Gate 回执、引用真实用户授权的 owner 记录及原始 Git commit 对象均须有可复核文件和哈希，不能用 ACCEPT 字符串、随机收据哈希或标签替代。完整源码字节计算出的 Git tree 必须匹配 commit 对象；安装副本无需 .git。启动和执行前重验全部证据；证据文件受保护，不能当原生凭据或源码挂载。现有 v1 Usable/Studio 记录保留原语义，不能用于新 v3 Stable。缺少绑定仍为 Development，独立 Session 入口拒绝 Stable，模型准入仍绑定 operator 哈希。公开状态只显示核验后的版本身份。真正审批、独立复核、Gate、合并及部署由外部流程完成，合成测试不构成发布批准。

部署 Stable 桥接时，将适配器副本和私有配置放在 Development 之外。配置固定现用 Stable 的批准记录及哈希与私有授权目录。固定外部监督在实际启动后写入每个 run 的独立授权，绑定控制目录、已有 Stable run，以及工作台的 run/source/candidate/graph/authorization 身份。外部 payload、逐 run 授权的 `binding` 与回执均必须包含 `acceptance_sha256`：对本次冻结任务卡的原始 UTF-8 字节计算 SHA256，保留换行及首尾空格，并与原 Stable run 的 `acceptance_sha256` 完全相同；旧授权缺此字段或任一身份不匹配均拒绝。桥接仅等待并读取，不创建授权。GitHub 客户端配置只由外部执行器读取。外部节点的参数协议仅支持固定哈希的绝对输入路径，以及解释器入口前的有限启动选项；不接受相对参数、`env` 的程序名查找、任意选项或字面配置。原桥接 CLI 本身仍接受 `--config` 等选项，但不要直接把这类参数写进工作台策略：应部署固定启动脚本，在脚本内绑定私有配置路径、配置哈希和 verify/delivery 类型，再以 `python -I -B <固定启动脚本绝对路径>` 调用。策略同时固定解释器、启动脚本、桥接脚本、配置及全部导入目录的哈希和最小挂载范围，私有运行数据作为单独挂载。旧的宽泛 argv 配置将拒绝执行，需先由部署者检查并改为固定启动器，不能静默降级。没有外部授权绑定的研发运行不能通过此桥接交付；本轮 DevFlower 自身交付仍由固定外部监督重新检查，不由新 Controller 自批。

前端重建：进入 `tools/studio/workbench_ui`，执行 `npm ci` 和 `npm run build`；也可将 `DEVFLOWER_UI_DEPS` 指向外部依赖缓存再执行 `build.mjs`，避免把 node_modules 放入源码候选。精确版本见 package-lock.json，许可证见同目录 THIRD_PARTY_LICENSES.txt。

画布纯编辑规则可执行 `node --test tests/workbench_editor.test.mjs`。原生 PTY 故障回归 `test_native_terminals.py` 使用真实 OS PTY 配合合成子进程，不能当作真实模型验收。

新增协议回归由 `test_workbench*.py` 运行；普通 Chromium/真实 HTTP 回归入口为 `tests/workbench_browser.py`。它使用明确标注的合成原生数据，不能替代真实 Provider、完整源码审核或用户最终验收。

### 工作台阅读与状态

打开文件夹后，可在左侧按 Provider 或“工作流 → 节点 → 会话”查看同一条原生会话，并筛选最近使用或正在运行。对话以 Markdown 展示，工具活动默认折叠；原生终端在接管前核验占用，不能与工作流同时写入。

设计画布编辑下一次流程；“本次运行”显示冻结快照。顶部总览来自持久化运行记录，显示当前节点、轮次、耗时、完成数和等待原因。暂停只停止新节点调度，当前调用可以继续；断网时旧运行结果隐藏为“状态待确认”，重连或刷新只读取同一运行。

点击连线查看当前运行的交接内容、字段、来源轮次、记录时间及接收状态；点击 Agent 展开“本次实际 Provider 请求”，核对初始化、每轮指令、上游数据和输出要求。初始化是否包含与实际输入发送回执分别展示；模型或 Provider 内部接收无法确认时明确显示 unknown。身份与完整请求放在可展开证据中，不能用模板补造历史。

短暂连线脉冲只由新收到的持久化交接事件触发，不重放历史动画；减少动态效果时保留文字接收状态。运行状态投影负例：`node --test tests/workbench_projection.test.mjs`。自动化产品测试通过不等于用户本人完成体验验收，也不授予 Stable 身份。

## 模型、关闭与请求检查

- 新建会话和 Agent 节点使用同一模型选择器。切换执行工具后读取该 Profile 的目录，点击“刷新模型”查询原生 Codex `model/list` 或已批准 Claude 中转站的 `/v1/models`。显示来源、成功更新时间、旧缓存和错误。代理没有该接口时，保留明确登记的配置并显示查询失败；这不是完整目录或物理后端证明。目录发现、操作者登记和执行准入分别检查。未登记模型不可启动；登记模型也不会自动获得执行准入。选择工作区、模型、effort 和工作方式后，点击“验证执行”，阅读说明并确认一次固定原生诊断调用。它使用独立 HOME 和空的只读诊断目录，不发送源码或任务。验证成功仅适用于此 Provider、精确模型、effort、模式、Profile、权限/工具、超时、工作区及已固定运行配置，5 分钟内有效；已获准调用的真实成功回执可原子续验同一配置，迟到成功不能覆盖撤销或新验证；变更配置、过期或真实调用失败后必须重验。物理后端与实际生效 effort 未由服务证明时继续显示 unknown。新建会话、工作流准备以及实际启动前都检查准入；目录刷新本身不触发模型执行。诊断会话保存在本地独立诊断区，不冒充业务会话。
- 切换模型时同步刷新该模型的 effort 选项。新建会话支持 Ask/Plan/Agent；前两种由运行器强制只读。权限、实际模型与本次消息在发送前冻结确认。已有会话沿用原 HOME/cwd/Provider/模型/effort，不能用切换下拉框冒充恢复。
- 关闭标签、节点配置、连线检查器或终端视图仅关闭显示。Escape 关闭最上层视图并恢复焦点；未发送消息和切换工作流时可选择保存、丢弃或取消。消息草稿按工作区和会话标签分别保存在此浏览器。原生历史不删除；结束 CLI 和停止工作流仍是单独的明确操作。
- 草稿节点旁可展开“输入/输出预览”和“本轮 Prompt 预览”，明确标为未执行模板，未知上游为 unknown。运行后点击连线进入“数据传递”，核对来源、目标、来源/目标轮次、字段、实际内容及 SHA-256。点击下游节点的“实际运行”查看 A–D 请求组成、E 完整可见请求、F 原生回执。这里读取持久化回合记录，草稿没有真实回执时明确说明，不能用模板补造。服务端逐字段接收和物理模型没有独立证明时为 unknown。
- 高级设置中声明输入/输出字段、类型及必需性。条件和路由只能读取输入合同声明的字段，缺少必需字段或类型错误会明确失败。输出合同在保存原生完成回执前验证；重新连接不能把无效输出当作成功。

## 规则路由与可选分类

“智能路由”按顺序匹配字段、运算符和比较值。每条输出连线必须选择已声明分支；没有匹配时进入默认分支，未配置默认分支则停止。条件节点对缺失/空字段可明确选择 ELSE 或停止；“不等于”不会把缺字段当作命中，运行后显示判断依据。未选分支显示“已跳过”。多个候选目标会在运行授权前全部检查权限，分类结果不能添加工具、路径或批准交付。

默认只执行确定性规则，不增加模型调用。需要语义判断时在节点旁勾选“仅当规则未命中时启用只读分类器”，选择工具、模型、强度、阈值和超时。类别只来自该节点已配置的分支，输出使用严格分类 Schema。无效 JSON、未知类别、低置信度或已确认结束的调用失败进入默认分支，保留原因和耗时；原生进程状态不明时停止，不通过 fallback 掩盖不确定的副作用。分类调用计入同一运行预算。
