# Agent 工作台

默认是独立的 Development 预览；部署者也可使用外部已批准的固定 Stable 副本，工作台本身不能签发批准。旧 Studio、v1/v2 草稿、授权和历史仍由原入口读取；v3 工作流另存，不迁移正在执行的旧任务。

## 日常操作

1. 从部署者提供的“打开工作台”入口进入。顶部及文件夹环境显示运行时核验的 Development 或 Stable 身份；私有登录地址不要公开分享。
2. 点击“打开文件夹”，在标明运行器机器的窗口选择目录。可返回父目录、选择已批准位置或最近目录，也可以取消。选择正常项目文件夹会绑定本机工作范围；浏览不会启动 Agent，执行和写入仍需确认本次任务权限。
3. 在右侧工具栏选择输入、Agent、条件、智能路由、汇合、循环、人工确认、输出、结束、验证和交付节点，或从“示例”开始。工作台支持顶部切换浅色、深色或跟随系统，采用左侧工作流/会话导航、中央自由画布、右侧工具/参数检查器、底部活动区。点击节点默认在右侧配置，画布为检查器预留空间；也可取消固定。拖动节点调整布局，从右侧连接点拖到下游左侧连接点。画布底部工具栏可框选、多选、缩放、适应画布、复制、粘贴、删除、对齐与分布、撤销和重做；空格或中键平移，滚轮缩放，缩略图导航。左侧导航、右侧检查器和底部活动区可拖动边缘调整大小；导航可收起，尺寸保存在本浏览器。从端口拖到空白处可搜索并添加下游节点；双击或右键空白画布可添加节点，拖入工具库节点可定位放置。节点右键提供复制、副本和删除，多选仍保持分组操作；连线旁的加号可插入节点，一次撤销恢复整个操作。复制 Agent 会新建原生会话。点选连线可改标签、指定交接字段或在连线上插入 Agent。
4. 基本页分别设置名称、职责、工具、会话、模型、强度和 Ask/Plan/Agent；提示词页设置初始化、每轮任务、输出要求；高级页限制权限、上下文、超时和预算。模型目录发现、部署授权、认证配置、实际推理成功是不同证据。真实目录中的其他模型可以直接选择；这只保存当前工作区的精确模型/强度，不代表已调用成功，发送前仍检查当前账号是否支持。已有会话显示其原始绑定配置；不能把新建会话的默认 Provider 用于恢复。
5. 填写本次任务，必要时点击“检查工作流”查看错误与提醒，然后点击“开始运行”。这次点击绑定工作区、图、模型、权限和预算；不要求输入模板化确认意见，也不先发 nonce 探针。实际 Provider 失败会显示原因，不自动重发。运行自动打开冻结画布；修改下一次流程需点击“编辑草稿”。历史运行可在画布工具栏切换。

检查结果针对点击检查时的画布与本次任务。点击错误可打开对应节点、嵌套循环或连线；修改后结果标为过期，撤销回原值也需重新检查。检查不调用模型，不能证明 Provider 实际执行成功。
6. 在节点上看真实状态、轮次、等待对象和结果；点击节点默认打开用户级运行对话，直接查看本次任务、当前轮上游输入、回答及实时可见工具活动。实际请求/回执仍可在“高级”展开。点击配置不会改变画布位置或缩放，适应画布必须显式点击。点连线查看按来源名称和内容展示的实际交接；固定/发送事件汇总为同一次交接，轮次和activation不同则保持独立。底部可展开事件和实际发送内容。暂停只停止新节点调度，当前进程继续；停止取消本任务拥有的进程。网络中断显示“状态未确认”，可点击“核验并恢复”，不能通过此按钮绕过原生完成回执或重发不确定的回合。进程身份、候选或回执不可靠时会明确拒绝恢复；已持久化终止的未确认运行只供查看，需另行授权新运行，勿重复启动。
7. 左侧搜索名称并打开同一原生会话。默认聊天显示可见消息；Claude 等工具把最终回答放入结构化输出时，下方直接显示“结构化执行结果”，标明运行、节点、完整轮次和当前流程状态。这些是已完成回合的实际结果，不冒充原生文本消息，不代表审核或交付批准。刷新页面会从当前工作区的会话索引重新打开上次会话并读取持久记录。完整请求、工具活动仍默认折叠；仅在 Provider 明确提供公开摘要时另列摘要；不展示隐藏推理。会话管理明确区分 DevFlower 别名/分类、原生改名/归档、可恢复回收站；没有自动过期或永久删除。点击“原生终端”会核验原环境、占用和必要的模型连接，直接打开或重连对应 CLI。明确点击才允许新建PTY；刷新只读取现存PTY，不重复启动。失败给出原因；已失败或撤销的连接只在明确点击“重试连接并打开”后重新验证，披露可能产生的单次调用费用。结果不明不自动重试。PTY 存活但尚无输出时显示“正在等待 CLI 输出”，不把进程存活当作 CLI 已就绪。高级连接设置可关闭自动打开，保留手动预览/确认流程。工作台始终使用原目录、Provider、模型、强度、HOME及原生UUID，不要求手写恢复命令。旧隔离模式的终端只读挂载源码。本机交互终端由用户控制原生 CLI 权限，并与工作流共用会话锁；不自动发送工作流输入或批准交付。若CLI仍出现升级菜单，会显示设置状态，请选择Skip，由操作者在工作台外管理升级。首次打开专用 HOME 时，仅继承操作者已完成的终端配色偏好；不会复制认证、项目信任或权限。若本机尚未完成配色设置或显式重置，终端会清楚显示设置阶段，需要在原生界面继续；目录信任和登录始终由操作者确认。旧隔离模式的 Claude 终端传入固定 Plan 和禁用自动/绕过批准的设置，外层强制只读；本机交互终端使用 CLI 自身配置，不宣称外层隔离。若 CLI 仍展示首次权限推广，界面会标明“等待原生权限设置”，先在原生菜单确认后再输入问题。普通聊天使用原生文本回答。旧工作流的结构化结果在终端上方另列真实执行结果并标明来源，不伪造原生聊天记录。关闭标签仅断开显示；“关闭此终端”停止其进程，原生历史保留。浏览器刷新或重新连接只读取已存在的 PTY，不重复启动或重发输入。输入结果不明时停止并标记需核验；服务重启不能冒充恢复丢失的 PTY。终端输出仅保留在服务内存，受大小和30分钟预算限制。

## 可执行语义与边界

- 顺序图、显式 fan-in 汇合、类型化条件和最多五轮的循环由确定性调度器执行。无界环和隐式多路 Agent 输入被拒绝；未选择分支显示跳过。汇合按运行、节点路径及完整祖先轮次关联输入。默认等待全部输入；条件分支之后可显式选择“汇合已选择分支”，仍等待所有上游终态后排除未选分支，失败/取消不会作为完整成功汇合。相同来源和目标拒绝重复连线。
- 每个 run+节点路径只拥有一个原生会话；首轮合并发送一次本次初始化，之后循环不重复。新运行即使恢复同一 UUID 也追加本次初始化，保留原历史。模型输出不是运行状态、独立审核或交付批准。
- 历史接口的 `messages` 保留原生可见消息；`execution_results` 单独投影已完成 Agent 激活的 `output.answer`，按执行起始时间排序，不从 StructuredOutput 工具输入猜测成功。关联同时核对工作区、cwd、Provider、HOME/配置根、原生 UUID，以及 run/节点/chat 绑定；完成回执还须匹配 UUID、请求模型/强度和成功进程结果。失败、取消、未确认激活及缺失/矛盾回执不产生结果。已完成回合若属于失败或状态未确认的流程，仍标出该流程状态，不宣称流程成功。相同回答的不同回合分别保留；原生文本已显示的同一回答不重复展示正文。查询结果按脱敏后的可见回答过滤，不能通过隐藏结构化字段命中；左侧搜索仍仅搜索名称与 Provider。此读取路径不恢复运行、不改写原生历史或 Controller 状态。
- 两个只读 Agent 可以并发；可写节点与同一源码的其他节点互斥。Ask/Plan 使用外层只读挂载，Agent 只能修改授权工作区；Git 元数据另行只读。提示词保护不能替代这些强制边界。
- 内置任务示例和新建 Agent 默认开启“接收本次任务目标”。每轮请求会单独列出本次运行冻结的原始目标与标准，再列上游实际结果；上游不能改写原标准。节点高级设置可以关闭，关闭后只使用该节点的提示词与连线输入。旧草稿和自定义节点没有此设置时保持关闭，旧运行不回填。实际请求和对话中的任务分区来自发送记录；草稿预览明确标为尚未发送。
- 传递最终回答、结构化字段或附件引用，不默认复制聊天历史。点选连线可看来源/目标 activation、完整轮次、实际字段和内容以及发送/接收阶段；点选下游节点显示初始化、职责背景、每轮任务、当前上游输入与输出要求组成的真实请求。交接先去掉私有回执、凭据字段和已知密钥，再选择字段；保留来源，超过预算明确截断，接收方重新核验附件访问权和内容哈希。上游建议不能增加权限。
- 原生恢复要求原 HOME、cwd、真实 UUID、模型/强度、记录身份与空闲状态均可核验。导入、多 cwd 或原环境不明的记录只查看或明确复制可见上下文新建。原生分叉创建新 UUID，保留父记录；独立审核不得复用开发会话。
- 状态与事件存储在 SQLite 事务中。重复启动必须匹配同一授权；恢复先检查真实进程、源码、原生记录和独立完成回执。结果不明的回合及原生元数据操作停止等待核验，禁止盲目重发。
- 验证/交付节点只接受部署者固定配置的外部执行器，浏览器不能提交命令。没有配置时显示具体缺项；没有真实审核、有效测试及远端读回不得声称交付。该 Development Controller 的研发由外部固定监督审核，不允许自批自身。
- `tools/devflower_stable_bridge.py` 是连接已授权 Stable 运行的部署适配器：验证节点核验 Stable 实际测试的完整套件、非零计数、进程与原始回执；交付节点重新执行 Stable 的完整门禁并正常推送、读回。中断后查询远端，不盲目重复推送；两库部分成功如实保留。它不会创建授权、批准 Stable 或把画布中 Agent 的 ACCEPT 当独立审核。
- Copilot 未通过本机认证、隔离执行及实际推理验证前不可选。原生 ACP 能力探测或空会话建立不等于模型验收。Provider 不可用会失败并跳过依赖节点，不伪造回答或换模型。

## 部署与开发

前端静态资源随仓库提供；普通启动不需要 Node/npm。部署者需 Python 3.11+、Git、Linux bwrap、显式隔离的原生工具及只读认证挂载。服务只监听 127.0.0.1，按端口隔离浏览器能力，不使用跨 localhost 端口的认证 Cookie；禁止将它直接暴露到公网。

高级部署入口是 `tools/devflower_workbench.py`，明确传入 operator、policy 及完整候选哈希。策略中的模型来自原生发现或有来源标注的显式登记；模型和 effort 沿用用户批准配置。源码变化需生成新的 Development 快照与配置 pin，不能覆盖运行中的 Stable。

正式 Stable 启动在 operator 中增加 `stable: {"record": "<外部批准记录绝对路径>", "sha256": "<外部固定的记录哈希>"}`，保留原 kind 和存储/HOME 路径。新 v3 必须使用 [version 2 来源证明](STABLE_PROVENANCE.md)：外部固定的实际 native hard-ACCEPT 结果、精确合同、旧固定 Gate 回执、引用真实用户授权的 owner 记录及原始 Git commit 对象均须有可复核文件和哈希，不能用 ACCEPT 字符串、随机收据哈希或标签替代。完整源码字节计算出的 Git tree 必须匹配 commit 对象；安装副本无需 .git。启动和执行前重验全部证据；证据文件受保护，不能当原生凭据或源码挂载。现有 v1 Usable/Studio 记录保留原语义，不能用于新 v3 Stable。缺少绑定仍为 Development，独立 Session 入口拒绝 Stable，模型准入仍绑定 operator 哈希。公开状态只显示核验后的版本身份。真正审批、独立复核、Gate、合并及部署由外部流程完成，合成测试不构成发布批准。

部署 Stable 桥接时，将适配器副本和私有配置放在 Development 之外。配置固定现用 Stable 的批准记录及哈希与私有授权目录。固定外部监督在实际启动后写入每个 run 的独立授权，绑定控制目录、已有 Stable run，以及工作台的 run/source/candidate/graph/authorization 身份。外部 payload、逐 run 授权的 `binding` 与回执均必须包含 `acceptance_sha256`：对本次冻结任务卡的原始 UTF-8 字节计算 SHA256，保留换行及首尾空格，并与原 Stable run 的 `acceptance_sha256` 完全相同；旧授权缺此字段或任一身份不匹配均拒绝。桥接仅等待并读取，不创建授权。GitHub 客户端配置只由外部执行器读取。外部节点的参数协议仅支持固定哈希的绝对输入路径，以及解释器入口前的有限启动选项；不接受相对参数、`env` 的程序名查找、任意选项或字面配置。原桥接 CLI 本身仍接受 `--config` 等选项，但不要直接把这类参数写进工作台策略：应部署固定启动脚本，在脚本内绑定私有配置路径、配置哈希和 verify/delivery 类型，再以 `python -I -B <固定启动脚本绝对路径>` 调用。策略同时固定解释器、启动脚本、桥接脚本、配置及全部导入目录的哈希和最小挂载范围，私有运行数据作为单独挂载。旧的宽泛 argv 配置将拒绝执行，需先由部署者检查并改为固定启动器，不能静默降级。没有外部授权绑定的研发运行不能通过此桥接交付；本轮 DevFlower 自身交付仍由固定外部监督重新检查，不由新 Controller 自批。

前端重建：进入 `tools/studio/workbench_ui`，执行 `npm ci` 和 `npm run build`；也可将 `DEVFLOWER_UI_DEPS` 指向外部依赖缓存再执行 `build.mjs`，避免把 node_modules 放入源码候选。精确版本见 package-lock.json，许可证见同目录 THIRD_PARTY_LICENSES.txt。

画布纯编辑规则可执行 `node --test tests/workbench_editor.test.mjs`。原生 PTY 故障回归 `test_native_terminals.py` 使用真实 OS PTY 配合合成子进程，不能当作真实模型验收。

新增协议回归由 `test_workbench*.py` 运行；普通 Chromium/真实 HTTP 回归入口为 `tests/workbench_browser.py`。它使用明确标注的合成原生数据，不能替代真实 Provider、完整源码审核或用户最终验收。

### 工作台阅读与状态

打开文件夹后，可在左侧按 Provider 或“工作流 → 节点 → 会话”查看同一条原生会话，并筛选最近使用或正在运行。对话以 Markdown 展示，工具活动默认折叠；原生终端在接管前核验占用，不能与工作流同时写入。

设计画布编辑下一次流程；“本次运行”显示冻结快照。顶部总览来自持久化运行记录，显示当前节点、轮次、耗时、完成数和等待原因。暂停只停止新节点调度，当前调用可以继续；断网时旧运行结果隐藏为“状态待确认”，重连或刷新只读取同一运行。

点击连线查看当前运行的交接内容、字段、来源轮次、记录时间及接收状态；点击 Agent 展开“本次实际 Provider 请求”，核对初始化、每轮指令、上游数据和输出要求。初始化是否包含与实际输入发送回执分别展示；模型或 Provider 内部接收无法确认时明确显示 unknown。身份与完整请求放在可展开证据中，不能用模板补造历史。

短暂连线脉冲只由新收到的持久化交接事件触发，不重放历史动画；减少动态效果时保留文字接收状态。运行状态投影负例：`node --test tests/workbench_projection.test.mjs`。自动化产品测试通过不等于用户本人完成体验验收，也不授予 Stable 身份。

## 模型、关闭与请求检查

- 新建会话选择 Provider、刷新模型目录，再选择模型、强度和模式。目录及模型选择不证明服务调用成功，也不改变执行权限。点击发送或开始时直接发起本次真实任务，实际结果以 Provider 回执为准；失败或未知结果不会自动重试。旧签定任务仍按其原有准入合同处理。
- 切换模型时同步刷新该模型的 effort 选项。新建会话支持 Ask/Plan/Agent；前两种由运行器强制只读。权限、实际模型与本次消息在发送前冻结确认。已有会话沿用原 HOME/cwd/Provider/模型/effort，不能用切换下拉框冒充恢复。
- 关闭标签、节点配置、连线检查器或终端视图仅关闭显示。Escape 关闭最上层视图并恢复焦点；焦点位于 xterm 内时，Escape 原样发送到唯一 PTY，终端视图保持打开，仍可通过“关闭终端视图”按钮断开显示；未发送消息和切换工作流时可选择保存、丢弃或取消。消息草稿按工作区和会话标签分别保存在此浏览器。原生历史不删除；结束 CLI 和停止工作流仍是单独的明确操作。
- 草稿节点旁可展开“输入/输出预览”和“本轮 Prompt 预览”，明确标为未执行模板，未知上游为 unknown。运行后点击连线进入“数据传递”，核对来源、目标、来源/目标轮次、字段、实际内容及 SHA-256。点击下游节点的“实际运行”查看 A–D 请求组成、E 完整可见请求、F 原生回执。这里读取持久化回合记录，草稿没有真实回执时明确说明，不能用模板补造。服务端逐字段接收和物理模型没有独立证明时为 unknown。
- 高级设置中声明输入/输出字段、类型及必需性。条件和路由只能读取输入合同声明的字段，缺少必需字段或类型错误会明确失败。输出合同在保存原生完成回执前验证；重新连接不能把无效输出当作成功。

## 规则路由与可选分类

“智能路由”按顺序匹配字段、运算符和比较值。每条输出连线必须选择已声明分支；没有匹配时进入默认分支，未配置默认分支则停止。条件节点对缺失/空字段可明确选择 ELSE 或停止；“不等于”不会把缺字段当作命中，运行后显示判断依据。未选分支显示“已跳过”。多个候选目标会在运行授权前全部检查权限，分类结果不能添加工具、路径或批准交付。

默认只执行确定性规则，不增加模型调用。需要语义判断时在节点旁勾选“仅当规则未命中时启用只读分类器”，选择工具、模型、强度、阈值和超时。类别只来自该节点已配置的分支，输出使用严格分类 Schema。无效 JSON、未知类别、低置信度或已确认结束的调用失败进入默认分支，保留原因和耗时；原生进程状态不明时停止，不通过 fallback 掩盖不确定的副作用。分类调用计入同一运行预算。

Jev 为 TypeSafe 的 System One 模型，官方提供带类别概率与置信度的 Choice API。SDK 的开源许可证不意味着模型权重开放。本机没有独立的 TypeSafe API key，未启用 Jev，也不将其他 LLM 称为 Jev。部署与性能结论以本地实际对比记录为准，未测量的质量、资源及成本为 unknown。

## 用户级操作与成本

- 删除工作流列表中的草稿需要确认并核对版本；保留历史运行、原生会话和不可变revision。有活动或待核验运行的关联草稿不能删除，迟到保存不能复活已删除的版本。
- 简单任务可直接“开始对话”，或用“单 Agent 快速任务”；多 Agent 是多次真实调用。工作流不会额外调用模型生成交接摘要，也不默认复制完整聊天历史。运行总览区分任务调用、运行内连接检查、实际耗时和Provider回报的Token；缺失字段不填假账单。Claude累计用量按精确Provider/HOME/session范围去重，不能逐轮累加。
- 当前普通对话与工作流直接使用所选模型执行任务，不要求登记模型或先做额外付费连接检查。开始按钮仍固定本次工作区、模型、模式、权限和预算；实际调用失败会显示原始原因，不自动重发。高级连接诊断及旧受控运行保留原有模型/effort/模式/Profile/权限/配置绑定，不能把其历史结果当作本次任务已经执行成功。
- 默认聊天只显示可见回答和工具活动。Provider没有流式输出时，明确显示真实进程仍在运行、等待可见输出；不把计时器当进度、不编造思考内容。仅Provider明确给出的公开推理摘要可展示。每个节点的原生记录按实际字节起止范围绑定该activation，后续循环内容不能混入前轮；完整原生会话是另外的历史视图。

受控会话的默认对话时间线来自匹配 workspace、Provider、原 HOME/cwd、原生 UUID、模型/强度和真实成功进程的运行/会话回执，按实际回合组成“你的问题 → Agent回答”。Claude只返回结构化结果时也能刷新后恢复回答；失败、取消、身份错配不会生成已完成回答。Provider原生可见文本与运行保存的结果来源在高级信息中区分，原生消息仍可展开查看；不把“No response requested.”协议占位当作Agent回答。

### 工作流归属与报告统计

草稿属于明确工作区；其他工作区不能保存覆盖、接管或删除它。尚无可靠归属的旧工作流单列为“未分配的旧工作流”，只能明确选择“在当前工作区新建副本”后保存新身份，原草稿、不可变修订及运行/原生历史保持不变。工作区接口不接受省略工作区的保存或全局删除；离线旧存储的修订/CAS兼容不构成工作区接口的接管权限。切换工作区会进入新画布，未保存流程先提供原有的保存、丢弃或取消选择。

交接按运行、连线、来源和目标 activation、目标轮次、attempt 及内容身份分组；同一交接的固定/发送记录合并，未知目标不猜测为某个已知回合。运行总览将任务调用、连接检查、Token 与“Provider 报告费用（非核验账单）”分开。费用只使用有限非负的实际报告；原生会话累计费用按 usage_scope 取最新报告，不能逐轮相加。缺失费用不补零，已知和未知混合时标注“部分报告”。

旧隔离模式的原生终端由外层执行器强制只读。本机交互终端使用原生 CLI 自身的权限提示，不承诺外层文件隔离。

## AI 配置与会话整理

画布顶部点击 **AI 配置**，描述目标、选择现有 Agent 和模型，确认后生成节点、连线和三个提示词的提案。预览后点击“应用到画布草稿”，可以一次撤销；应用不会自动保存、启动任务或授予写入/交付权限。生成一次模型调用，必要的连接检查另计，最多120秒，不自动重试；配置模型仅接收已展示的任务/画布配置，不能读取工作区源码。关闭面板不会取消后台生成，重新打开可查看同一提案。支持顺序、只读并行汇合；复杂条件和有界循环仍在画布配置。没有捆绑下载离线模型，使用本机已批准的 Codex / Claude 通道。

外部AI可读取认证的 `GET /api/config-assistant/schema?workspace=…`，按返回的 schema、可用 Agent/模型选择构造 version=1 计划，再通过 `POST /api/config-assistant/proposals` 提交 `{workspace,graph,plan}`，或在助手中导入同格式计划文件。`graph` 是当前完整草稿快照；接口只生成提案，需单独确认应用；草稿/源码/配置变化后旧提案不能覆盖新编辑。外部来源标为未验证，无原生回执时明确 unknown。不要把本地私有登录凭据发送给外部AI。接口不接受新服务地址、API密钥、命令或授权字段。

会话分组标题和节点标题可点击折叠，浏览器按工作区记忆。管理会话直接显示重命名、归档、回收站或恢复按钮；原生工具操作独立折叠展示。按 Workflow 分组后，标题旁垃圾桶可把已列出的整组会话移入可恢复回收站：确认前固定成员，任何占用或成员变化都会拒绝整批操作。不删除原生历史、历史运行或停止进程；永久清理不属于此按钮。

# 同一原生进程的本机终端连接（Development）

打开某个真实会话的「原生终端」，再点「在本机终端连接」。在本机终端执行显示的命令可实时观察同一个 Codex/Claude Code CLI；添加 `--takeover` 明确接管输入。`Ctrl-]` 只断开本机显示，不退出 Agent。工作台继续显示输出；点「接管到工作台」可取回键盘。旧端的排队按键被代次检查拒绝，断网不重放。断开接管端后，输入保持未接管，需主动取回。

这里复用一个受监督 PTY、一个原生进程及其原来的 HOME/cwd/session ID，不运行第二条 `--resume`、不复制原生历史。连接文件位于本机私有临时目录，权限 0600，socket 仅允许同一系统用户和持有能力的连接；退出原生终端后失效。工作流与终端共用会话租约；本机交互终端的权限由原生 CLI 管理。直接在外面另起不受管的 `claude --resume` 不是本功能的连接方式。

上述旧隔离模式的 HOME 不能直接当作桌面会话库。旧版本的桌面同步结论只适用于该配置；下文的本机原生模式使用原来的会话库，不依赖复制或导入历史。

## 本机原生模式（Development）

本机原生模式不为每次运行另建 HOME，不额外套一层容器。Codex 使用当前用户的 `.codex` 与官方 app-server；Claude Code 使用当前用户的 `.claude` 与原中转配置。打开历史只读取原生记录，不自动导入或复制到项目记录区。已受工作台管理的完成回合仍可按既有归档规则记录到项目 `.devflower`。

工作台与原生客户端使用同一个真实 UUID。Codex 的原生写锁决定哪一端可以继续：另一端占用时工作台拒绝启动，请先在原客户端结束或释放会话，再刷新并明确接管。读取历史不持有写锁、不启动新回合。工作台中的多个不同会话可以共用 HOME，不再互相阻塞。工作台创建的原生会话是否出现在桌面列表还受桌面工作区、来源筛选及刷新行为影响；不能把共同存储等同于已实现桌面活动回合的热接管。

工作台内的会话与终端共用单会话写入锁；同一活动 PTY 可双端观察并明确切换键盘。Claude 会话只有在本机受管请求、进程、成功回执和原生历史快照均能对应时才可续聊或新开受管终端。受管终端正常退出后，监督器在持有会话锁期间核验子进程与原生历史并保存快照，随后可继续该会话；关闭视图不会退出进程。历史变化、异常退出、缺少证明和外部未受管会话只能只读查看。早期没有历史快照证明的记录不会自动获得续写权限。Claude 未提供已核验的跨客户端原子写锁：外部直接调用原生 CLI 不受工作台锁控制，不能声称已互斥。

本机原生模式沿用 CLI 自身的权限，不再承诺外层强制隔离。Codex Ask/Plan 使用原生只读，Agent 使用原生工作区写权限。Claude 当前开放 Ask/Plan；其写入边界尚未验证，因此工作台禁用 Agent 写入。额外的 Skills 挂载、定制子 Agent 和自动交付节点在本机模式中暂不开放，不能把旧隔离模式的保护证明套用过来。模型目录不证明实际调用成功，也不授予执行权限。

运行设置由本机启动入口固定，普通用户无需手写配置。部署者可在签定的 operator 中加入 `native_local`，分别明确 `codex`/`claude` 的 `home` 和 `config_root`；当前要求会话根严格为该 HOME 的 `.codex`/`.claude`、归本机用户所有。缺少此配置时保持旧模式，不静默切换已有运行、旧 HOME 或 Stable；不会改写全局认证或中转配置。本机用户选择不隔离不等于自动批准新的 Stable。

普通本机 Codex 续聊使用 CLI 取得原生写锁时加载的最新历史；CLI 不提供锁内上一回合的原子比较。DevFlower 展示的是本轮发送的可见输入，原生历史可能另外进入 Provider 上下文；这不是完整服务端请求。需要严格历史比较或自动交付的流程仍须使用已验证的隔离监督路径。普通运行的本地机械探测使用合成 Provider，不是付费模型验证；若原生写边界无法验证则拒绝发送。

受控的本机 Codex 回合使用 CLI 的具名权限配置：允许读取普通文件、按工作方式限制工作区写入，并拒绝工具访问本机权威状态、正在运行的框架目录和已知认证路径。启动前分别检查原生权限、实际模型工具和未选功能的关闭状态；探测不可用时显示 CLI 原因并拒绝发送。用户明确接管 Codex 交互终端时也传入该具名配置，内置工具的默认权限受此配置约束；用户仍可操作原生 CLI，外部 MCP 和用户在 CLI 中改变权限不受此配置保证。终端不接收工作流自动任务，终端操作不构成交付批准。

Development 的普通本机 Codex 对话、工作流和受管终端可以选择包含受保护子目录的父工作区。工作台在服务端排除受保护目录、认证和运行中的框架，并把这个部分视图与本次点击绑定；它不是完整源码身份。实际发送前仍须通过本机 CLI 的权限能力检查；受保护文件的硬链接如果全部位于保护范围内且归属可核验，可正常保留，发现未知别名或检查期间发生变化时停止。父工作区不能用于外部验证或自动交付，部分视图仍保守拒绝普通文件的多重硬链接。受管 Claude 交互终端以空内置工具集和严格空 MCP 配置启动，保留原生对话；尚未验证其逐路径读写规则，因此不开放文件或 Bash 工具，也不将用户原生配置视为交付授权。
